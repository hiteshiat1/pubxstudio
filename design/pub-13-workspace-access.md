# PUB-13: Workspace access and roles

The authenticated boundary uses a GitHub OAuth web flow to establish an application identity. The founder's numeric GitHub ID, configured as `PUBX_FOUNDER_GITHUB_ID`, may create the first workspace once; other accounts must be added by a founder. GitHub OAuth is used only for identity. The GitHub access token is not stored. The application session uses a random opaque cookie (`HttpOnly`, `SameSite=Lax`, `Secure` on HTTPS); only its SHA-256 hash is stored in PostgreSQL. Sessions expire after seven days and are revoked on sign-out. OAuth state is random and checked before code exchange. See [GitHub's web flow](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps).

`db/access.mjs` enforces founder, approver, and operator roles from current database membership on every workspace query. `GET /api/workspaces` lists only the current user's workspaces. `GET /api/workspaces/{workspaceId}/accounts/{accountId}` returns a scoped account summary without credential bytes. Cross-workspace reads return a generic unavailable result. Founders can add an invited GitHub ID with `POST /api/workspaces/{workspaceId}/members` (`{"externalSubject":"github:123","role":"operator"}`) and change an existing member with `PATCH /api/workspaces/{workspaceId}/members/{userId}` (`{"role":"approver"}`). Write routes require a matching `Origin` header and an active founder session. The last founder cannot be demoted. IDs and roles must be checked in the database, not trusted from a client request.

The `/studio` editor still supports local draft generation without a session; it has no access to workspace records. The former global server filesystem save was removed, leaving browser ZIP export. Server-side social publishing remains disabled. Future approval, account, and queue routes must use this session boundary and workspace-scoped queries. The founder must configure the GitHub OAuth app and server environment as described in [manual actions](../MANUAL_ACTIONS.md); mocked OAuth tests do not establish a production login.

Verification: `npm run test:db` against a disposable PostgreSQL instance covers migration 004, token hash storage, cross-workspace object denial, role changes, last-founder protection, expired/revoked sessions, founder bootstrap, invalid state, and uninvited GitHub account denial. `npm run build` verifies the Next.js routes compile. An HTTP smoke test against the built app and disposable database confirmed anonymous `401`, scoped account `200`, cross-workspace `404`, and missing-origin mutation `403`. No live OAuth callback was performed.
